## 구현 범위

V10은 `SourceArtifact`에 파일명, 바이너리, 크기를 추가하고 `CSV`, `XLSX` 원본과 추출 방식을
허용한다. 파일은 2MB 이하로 제한해 현재 PostgreSQL `BYTEA`에 함께 보존한다. 공급처별 문서량과
보관 기간이 확인되기 전에는 Object Storage 운영 복잡도를 추가하지 않는다. SHA-256은 업로드한
원본 바이트 그대로 계산하며 같은 조직·공급처·해시는 기존 검토 초안을 반환한다.

`POST /api/v1/supplier-offer-drafts/import`는 multipart로 공급처, 통화, 선택적인 원본 위치와 파일을
받는다. OWNER, ADMIN, OPERATOR만 업로드할 수 있고 조회는 기존 조직 경계를 따른다. 화면은 파일
메타데이터와 해시, 자동 추출 후보와 행별 오류를 보여준다. 사용자가 행을 확인하면 추출 오류가
지워지고 기존 구매 선택·견적·원가·발주 흐름을 그대로 사용한다.

## 파서 계약과 안전 경계

- CSV는 UTF-8과 BOM, RFC 스타일 따옴표·쉼표·개행을 처리한다.
- XLSX는 첫 번째 표시 시트와 셀의 저장값만 읽는다. 수식은 실행하지 않고 검토 경고를 남긴다.
- VBA 매크로, XML 외부 엔터티·DOCTYPE, 시트 경로 이탈을 차단한다.
- 파일 2MB, 압축 해제 8MB, ZIP 항목 200개, 열 50개, 데이터 행 200개로 제한한다.
- 필수 의미 열은 상품명이다. 지원 별칭에는 상품명/제품명/품명/name/product_name/description이 있다.
- SKU, MOQ, 단위, 단가, 원산지, 비고는 한국어·영어 별칭을 매핑하며 같은 의미의 중복 헤더는 거절한다.
- 문서 자체가 잘못됐으면 전체 요청을 거절한다. 숫자·단위·원산지 문제는 행별 오류로 보존한다.

## 합성 fixture와 검증 결과

실제 공급처 샘플이 없으므로 `supplier-offer-synthetic.xlsx`를 테스트 fixture로 만들었다. 정상 행 2개,
숫자가 아닌 단가 1개, MOQ는 있지만 단위가 없는 행 1개를 포함한다. 이 fixture는 파서 단위 테스트와
PostgreSQL multipart 통합 테스트가 함께 사용한다. 통합 테스트는 원본 메타데이터·해시·추출 후보,
행별 오류, 재업로드 중복 방지, 다른 조직 조회 차단과 VIEWER 업로드 금지를 확인한다.

합성 fixture는 계약과 실패 처리를 고정하기 위한 것이며 실제 공급처의 병합 셀, 다단 헤더, 날짜·통화
표시 형식과 임의 시트 배치는 입증하지 않는다. 첫 실제 샘플을 받을 때 원본을 익명화해 회귀 fixture로
추가하고, 기존 규칙으로 처리되지 않는 변형만 명시적으로 확장한다.
