# 고객 발굴 · 인터뷰 요청 아웃바운드 — 단일 파일판

## 목적과 경계

계약을 따는 판매 메일이 아니라 문제를 확인하는 인터뷰 요청을 만든다. 목표는 30통 자체가 아니라
답장 5건과 인터뷰 2건에서 고객의 실제 말을 얻는 것이다. 이 파일만 사용하며 별도 스크립트,
참조, 템플릿을 찾지 않는다.

자동 로그인은 금지한다. 실제 발송은 되돌릴 수 없으므로 검증·미리보기·사용자 명시 승인을 모두
거친 뒤에만 한다. 사용자가 테스트, 초안, 임시저장을 말하면 실제 발송 동작을 절대 실행하지 않는다.

## 결과 경로

```text
~/Downloads/AI마케팅실습/
├── 01_내비즈니스/icp.json, icp.md
├── 02_타깃발굴/targets.csv
├── 03_메일검증/verified.csv, invalid.csv, verify_report.md
├── 04_메일초안/draft_001.md ..., 초안목록.csv, preview.html
├── 05_발송기록/sent_log.csv, replies.csv, 결과요약.md
└── _설정/config.json
```

폴더가 없으면 만든다. 기존 데이터가 다른 제품이면 섞지 말고 사용자에게 알린다.

## 0. 준비

필요한 값은 대화로 받는다.

- 발신자 이름
- 발신 이메일
- 제품 한 줄
- 실행 모드: 조사만 / 초안까지 / Gmail 임시보관 / 실제 발송

`config.json`:

```json
{
  "발신자이름":"", "발신자메일":"", "제품한줄":"",
  "일일발송상한":10, "총목표인원":30,
  "발송방식":"gmail-web", "크롬포트":9222
}
```

브라우저 조작이 필요하면 기존 로그인 브라우저나 제공된 브라우저 도구를 사용한다. 로그인되지
않았으면 로그인 화면까지만 열고 사용자에게 직접 로그인하도록 요청한 뒤 멈춘다. 비밀번호·2FA·
캡차를 자동 입력하지 않는다. 사용자의 기존 브라우저에 원격 연결했다면 브라우저 전체를 닫지 않는다.

## 1. ICP 확인

`01_내비즈니스/icp.json`이 있으면 먼저 읽고 제품과 일치하는지 확인한다. 없거나 부족하면 다음을
한 번에 하나씩 묻는다: B2C/B2B/B2G, 업종·상황, 규모, 지역, 실제 만날 사람, 겪는 문제,
웹에서 관찰 가능한 특징, 제외 조건.

검색쿼리는 최소 8개를 만들되 고정 문장을 붙이는 방식으로 만들지 않는다.

- 문제 신호: 고객이 실제로 쓰는 불편 표현, 대안 불만, 구독 피로
- 정체성 신호: 직책, 직군, 업종, 지역, 조직 규모
- 행동 신호: 관련 글 작성, 행사 참여, 채용, 도구 템플릿 판매, 커뮤니티 운영
- 출처 신호: 협회 회원사, 행사 참가자, 공식 디렉터리, 공개 포트폴리오, 공식 문의 페이지

B2C에서 개인 이메일을 무리하게 수집하지 않는다. 공개적으로 업무 연락을 받는 제작자·사업자·
커뮤니티 운영자·전문가부터 찾는다.

`icp.md`에는 조건과 검색 전략을 사람이 읽을 수 있게 요약한다.

## 2. 웹 전체에서 후보 발굴

한 검색엔진과 첫 페이지만 기계적으로 훑지 않는다. 검색 결과가 빈약하면 검색 의도를 바꾸고,
후보 사이트의 소개·문의·저자·프로필 페이지까지 따라간다.

### 다단계 조사

1. 문제를 직접 호소한 글과 댓글을 찾는다.
2. 현재 대안·경쟁 도구의 후기와 템플릿 제작자를 찾는다.
3. 관련 커뮤니티·협회·뉴스레터·교육 운영자를 찾는다.
4. 후보의 공식 홈페이지와 소개 페이지에서 대상 적합성을 확인한다.
5. 공개된 업무용 문의처가 있는 경우에만 후보에 넣는다.
6. 이름+이메일과 이름+근거URL을 기준으로 중복을 제거한다.

후보마다 “왜 이 사람인가”를 설명하는 근거 문장을 직접 쓴다. 이메일이 있다는 이유만으로 후보에
넣지 않는다. 검색 결과 페이지, 로그인 페이지, 언론사 대표주소, 웹마스터, 무관한 기자 주소,
페이지 소스의 개발용 주소는 제외한다.

`targets.csv`의 UTF-8 BOM 열:

```text
이름,유형,업종,지역,이메일,전화,홈페이지,근거URL,검색어,개인화근거,수집일
```

한 후보를 확인할 때마다 저장한다. 각 요청 사이에 적당한 간격을 두고, 차단·캡차가 나오면 우회하지
말고 사용자에게 화면 확인을 요청한다.

## 3. 이메일 검증

검증을 건너뛰지 않는다. 검증은 실제 본문을 보내지 않는다.

1. 문법: 로컬파트@도메인과 허용 문자 검사
2. MX: 도메인이 수신 메일 서버를 가지는지 확인
3. SMTP: 환경과 정책이 허용할 때 `RCPT TO`까지만 확인하고 `DATA`는 절대 보내지 않음
4. Catch-all: 무작위 존재하지 않는 주소도 받아주면 판정불가

결과는 `유효`, `판정불가`, `무효`로 나눈다. SMTP 25번 포트가 막혔으면 MX까지만 검사했다고
명시한다. 판정불가는 유효라고 가장하지 않는다.

`verified.csv`와 `invalid.csv`에는 원래 후보 열에 다음을 추가한다.

```text
검증결과,검증단계,검증사유,검증일
```

`verify_report.md`에는 전체·유효·판정불가·무효 수와 비율, SMTP 가능 여부, 부족한 후보 수를 쓴다.

## 4. 개인화 인터뷰 메일 작성

각 메일의 첫 문장은 후보의 실제 글·활동·도구·커뮤니티와 연결한다. 이름과 홈페이지 URL만 바꾼
동일 문장은 개인화가 아니다. 근거URL의 내용을 읽지 못했으면 초안을 만들지 말고 `검토필요`로 둔다.

기본 구조:

```text
제목: {이름 또는 조직} 담당자님께 15분만 여쭙고 싶습니다

{이름}님, 안녕하세요.

{후보의 실제 활동을 언급하는 구체적인 개인화 근거 1~2문장}

저는 {제품}을 만들고 있는 {발신자}입니다. 아직 파는 단계가 아니라,
제가 생각한 문제가 실제로 존재하는지 확인하는 중입니다.

여쭙고 싶은 것은 하나입니다. {고객이 겪는 문제}가 실제로 불편한지,
아니면 이미 다른 방식으로 해결하고 계신지입니다.

15분이면 충분합니다. {실제 가능한 날짜 두 개} 중 편한 시간이 있으실까요?
전화도 좋고 온라인도 좋습니다.

관심 없으시면 회신하지 않으셔도 괜찮습니다. 시간 내주셔서 감사합니다.

{발신자} 드림
{발신자메일}
```

첫 메일에는 판매 링크, 과장, 가짜 친분, 확인하지 않은 칭찬을 넣지 않는다. 날짜는 현재 날짜를
기준으로 실제 요일과 일치해야 한다.

각 `draft_NNN.md`의 프론트매터:

```yaml
---
받는사람: name@example.com
제목: 실제 제목
이름: 후보 이름
검증: 유효 또는 판정불가
근거URL: https://...
---
```

`초안목록.csv`에는 번호·이름·이메일·제목·검증·근거URL·상태를 쓴다.

`preview.html`은 외부 파일 없이 열리는 단일 HTML이다. 전체 대상 목록과 모든 메일 본문을 카드로
표시하고, 검증 결과·근거URL·개인화 근거를 함께 보여준다. 잘못된 이름, 빈 근거, 중복 본문,
미확정 날짜를 눈에 띄게 경고한다.

## 5. Gmail 임시보관과 실제 발송

### 실행 모드 구분

- `초안까지`: 로컬 파일과 preview만 만든다.
- `Gmail 임시보관`: 편지쓰기 → 받는 사람·제목·본문 입력 → Gmail의 `저장 및 닫기`만 수행한다.
- `실제 발송`: 별도의 명시적 승인 후에만 발송한다.

Gmail 임시보관 모드에는 발송 버튼 클릭, `Cmd/Ctrl+Enter`, 전송 API 호출을 포함하지 않는다.
각 초안을 닫은 후 임시보관함 목록에서 정확한 제목을 다시 확인한다. 제목과 마지막 문장을 재조회할
수 있으면 함께 검증한다. 실패하면 저장 완료라고 말하지 않는다. `gmail_draft_log.csv`에 제목,
받는 사람, 저장 시각, 재조회 결과를 남긴다.

실제 발송은 다음 조건이 모두 참일 때만 가능하다.

1. 이메일 검증을 완료했다.
2. 사용자가 `preview.html`을 검토했다.
3. 받는 사람 목록과 첫 통 전문을 사용자에게 보여줬다.
4. 사용자가 바로 그 배치의 실제 발송을 명시적으로 승인했다.
5. 오늘 성공 발송 수가 10통 미만이다.

승인 전에는 `--yes`에 해당하는 확인 우회를 하지 않는다. 한 통마다 성공 확인 후
`sent_log.csv`에 날짜시각·이름·이메일·제목·방식·상태를 즉시 추가한다. 실패를 성공으로 기록하지
않으며 오늘 10통을 넘기지 않는다.

## 6. 회신 분석

`replies.csv`:

```text
발송일,이름,이메일,제목,답장,인터뷰,답장일,고객원문,메모
```

사용자가 받은편지함을 확인하고 `답장`, `인터뷰`, `고객원문`을 채운다. 고객이 쓴 표현은
바꿔 쓰지 않는다.

`결과요약.md`에는 날짜별 발송량, 누적 발송, 답장 수·회신율, 인터뷰 수를 쓴다.

- 10% 이상: 인터뷰를 잡고 고객 언어를 축적
- 3~10%: 첫 두 줄과 후보 목록을 개선
- 0~3%: 목록 → 메시지 → 문제 가설 순으로 의심

답장 0도 데이터다. 임의로 성공처럼 해석하지 않는다.


## 완료 보고

후보 수, 검증 결과, 초안 수, Gmail 임시보관 수, 실제 발송 수를 각각 구분해 보고한다.
실제 발송이 0이면 명확히 `0통`이라고 쓴다. 주요 CSV·HTML 파일을 클릭 가능한 경로로 제공한다.
