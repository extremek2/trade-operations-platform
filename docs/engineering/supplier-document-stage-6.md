# P6 여섯 번째 단계: 문서 추출 결과와 공급 제안 초안 연결

- 날짜: 2026-09-22
- 상태: 개발 환경의 합성 PDF와 모의 추출기로 구현·검증 완료
- 운영 적용: 미실시. 실제 공급처 문서 형태와 저장소·보관 정책 검증 필요

## 구현

- 기존 `POST /api/v1/supplier-documents/import`로 원본을 보관하고 PDF 텍스트 추출 또는 OCR을 실행한다.
- `POST /api/v1/supplier-documents/{documentId}/draft`는 추출에 성공한 조직 소유 문서와 통화를 받아 기존 `ExtractionRun`에 연결된 `SupplierOfferDraft`를 만든다. 같은 문서를 다시 요청하면 기존 초안을 반환한다.
- 추출 텍스트의 비어 있지 않은 각 행을 원본 위치가 있는 검토 후보로 가져온다. 최대 200행, 후보당 500자다. 긴 행은 경고를 남기고 전체 텍스트를 원본 추출 결과에 보존한다.
- 알려진 SKU·상품명·MOQ·단위·단가·원산지 표 행은 필드 후보로 제안한다. 불확실한 행은 원문 그대로 둔다. 모든 행은 `PENDING`이며, 머리글과 상품이 아닌 행도 사용자가 확인하거나 제외해야 초안을 확정할 수 있다.
- 공급 제안 화면에 PDF/PNG/JPEG 업로드, 문서 상태·추출 텍스트, 인증된 원본 미리보기, 통화 지정·초안 생성, 기존 행 검토·구매 선택을 연결했다.
- 추출 실패 문서는 원본과 오류를 표시하며 초안을 만들지 않는다. 재추출은 다음 단계 과제로 남는다.

## 원본 대조 화면

- 문서 검토 초안을 만들면 문서 카드 안에서 왼쪽 원본 PDF·이미지와 오른쪽 수정 가능한 디지털 품목 표를 함께 보여 준다. 좁은 화면에서는 원본과 품목 카드를 위아래로 배치한다.
- SKU·상품명·수량·단위·단가·원산지가 파싱된 행은 입력값을 미리 채운다. 상품 외 문구는 접어 두되 다시 펼쳐 품목으로 선택할 수 있다.
- OCR 작업기는 글자별 점수에서 행별 가중 평균을 계산한다. 행 OCR 점수가 95% 미만이거나 점수를 연결할 수 없으면 원본 대조를 강조한다. 이 점수는 상품 정보의 정확도나 필드별 확률이 아니다. 기존 OCR 추출 결과에 행별 점수가 없으면 미확인으로 표시한다.
- 선택한 품목은 상품명과 양수 수량·단위를 입력하고 각 행의 `대조 완료`를 체크해야 진행 버튼이 활성화된다. 확인되지 않은 단가는 비워 둘 수 있다.
- `POST /api/v1/supplier-offer-drafts/{draftId}/review`가 모든 원본 행의 확인·제외 결과를 한 트랜잭션으로 적용하고 초안을 확정한다. 버전·중복·누락 행을 검사한다. 확정 후 같은 문서 카드에서 구매 후보를 선택한다.

## 검증

- 행별 OCR 점수와 일괄 검토 화면을 추가한 뒤 문서 통합 테스트·후보 파서 테스트, OCR 컨테이너 테스트 3개, 공급 제안 화면 테스트 6개, 프런트엔드 배포 빌드를 통과했다. 합성 흐린 PDF를 Chrome에서 열어 행별 경고·수정·대조 체크 동작을 확인했다.
- `./gradlew test --tests '*SupplierDocumentIntegrationTest' --no-daemon`: 통과. 문서→초안→행 확인→구매 선택, 같은 문서 중복 생성, 조직 격리, 추출 실패를 검증했다.
- `./gradlew test --no-daemon`: 전체 127개 중 126개 통과, 1개 skip, 실패 0건.
- `CI=true npm test -- --watchAll=false --runInBand`: 13 suite, 55 test 통과.
- `npm run build`: 배포용 프런트엔드 빌드 통과.
- 실제 공급처의 다단 표와 문장형 문서에서 상품 후보를 정확히 구분하는 작업은 실제 문서 샘플로 검증해야 한다. 현재 후보화는 OCR 텍스트 행 단위이며 구매 가능한 데이터로 자동 확정하지 않는다.
