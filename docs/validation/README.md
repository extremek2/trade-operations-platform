## 목표

샘플로 완주한 거래 사이클을 실제 또는 실행 가능한 상품 3개에 적용한다. 최소 1개는 실제 해외
구매·배송·비용 자료를 사용한다. 예상 원가와 실제 원가, 검토 시간, 수정 필드, 누락 항목과 다음
매입 결정을 증거와 함께 남긴다.

이 단계에서는 기능 수를 늘리지 않는다. 실제 입력을 막는 문제만 고치며, 자동화·채널·공급처
어댑터는 파일럿에서 반복 병목이 확인된 뒤 결정한다.

## 파일럿 선정 기준

세 상품은 가능한 한 다른 입력 경로를 사용한다.

1. 국내 도매 API 또는 사이트 수동 확인 상품
2. 실제 CSV/XLSX/PDF 견적을 가진 공급처 상품
3. 실제 해외 구매·배송·통관 또는 이에 준하는 실행 가능한 상품

각 상품은 다음 조건을 충족해야 한다.

- 원본 가격·수량·조건의 출처와 확인 시각을 기록할 수 있다.
- 자료의 사용·보관 권한과 익명화 범위를 확인할 수 있다.
- 예상 원가와 실제 비용 또는 아직 미확정인 값을 구분할 수 있다.
- 판매, 구매의향 또는 중단 근거 중 하나를 관측할 수 있다.
- 테스트용 합성 자료인지 실제 자료인지 명확히 구분한다.

## 측정 계약

| 지표 | 기록 시점 | 최소 필드 |
|---|---|---|
| 수직 흐름 완주 | 다음 행동 결정 시 | pilot ID, SKU, 조달 경로, 시작/종료 시각 |
| 예상·실제 원가 차이 | 실제 원가 마감 시 | 예상액, 실제액, 차이액·차이율, 원인 |
| 검토 시간 | 제안 검토·원가 마감 전후 | 시작/종료 시각, 행·문서 수 |
| 자동 추출 수정 | 문서 검토 확정 시 | 제안 필드 수, 수정·삭제·추가 필드 수 |
| 데이터 누락 | 단계 인계 시 | 필수 미확정 값, 담당, 확인 예정일 |
| 재사용 | 두 번째 건 생성 시 | 재사용한 상품·거래처·견적·규칙, 절약 시간 |
| 다음 결정 | 사이클 종료 시 | 재발주·관찰·중단, 이유와 근거 위치 |

개인정보, API 키, 비밀번호, 원본 거래 비밀은 이 문서에 기록하지 않는다. 증거는 접근이 제한된
저장 위치의 식별자만 남긴다.

## 실행 순서

1. [파일럿 케이스 템플릿](v0-pilot-case-template.md)을 상품별로 복사한다.
2. 원본 자료와 보관 권한을 확인하고 `pilot_id`를 발급한다.
3. 기존 화면만 사용해 후보부터 다음 결정까지 진행한다.
4. 막힌 지점은 데이터 문제, UX 문제, 도메인 규칙 문제, 외부 연동 문제로 분류한다.
5. 실제 진행을 막는 문제만 재현 테스트와 함께 수정한다.
6. 세 상품 완료 후 자동화·성능·SaaS 전환 우선순위를 다시 판정한다.

## 현재 차단 조건

- 아직 파일럿 대상 상품과 실제 원본 자료가 저장소에 제공되지 않았다.
- GitHub CLI 인증이 만료되어 자동 PR 생성은 할 수 없다. 종료 브랜치는 원격에 반영됐으며 PR은
  GitHub에서 `feature/end-to-end-trade-cycle` → `main`으로 생성해야 한다.
- 도매꾹 라이브 테스트와 MinIO 왕복 테스트에 필요한 환경변수는 설정되지 않았다.
