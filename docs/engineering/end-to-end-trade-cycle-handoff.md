- 인계일: 2026-11-06
- 종료 브랜치: `feature/end-to-end-trade-cycle`
- 코드 기준점: `d695aa0` (`fix: serialize trade cycle aggregate updates`)

- 다음 작업 브랜치: `feature/v0-real-data-validation`

## 1. 이번 단계의 결론

조직 가입과 권한부터 공급 제안, 견적, 예상 원가, 발주, 선적 또는 국내 입고, 실제 원가,
판매 관측과 재발주 판단까지 하나의 웹 흐름으로 연결했다. 도매 카탈로그와 문서 OCR도 같은
제안 검토 흐름으로 들어오며, 샘플 E2E에서 국내 매입 사이클을 완주한다.

기술 흐름을 더 넓히는 작업은 여기서 중단한다. 다음 단계의 핵심 질문은 기능 구현 가능성이 아니라
실제 상품과 문서로 원가 누락과 반복 입력을 줄이고 다음 매입 판단에 도움이 되는지다.

## 2. 구현 완료 범위

- 계정, 이메일 확인, 조직 승인, 조직 역할, 외부 건별 참여와 철회
- 조직별 상품, 거래처, 공급 견적 개정과 예상 원가 시나리오
- 다품목 발주, 선적 배정, 부분 입고, 재고 로트, 실제 원가 배부와 마감
- 판매 관측과 상품별 재발주·관찰·중단 결정
- 수동, CSV/XLSX, PDF/이미지 공급 제안 접수와 행별 검토·구매 선택
- S3 호환 원본 보관, 텍스트 PDF 추출, OCR, 실패 이력과 수동 재추출 API
- 공급처 문의 Gmail 작성 창 인계
- 도매꾹 샘플/라이브 조회 어댑터, 구간가, 발주 전 가격·재고 재확인
- 국내 재고 매입의 외부 주문 기록과 선적 없는 입고
- 운영 Compose, 별도 migration 계정, HTTPS 프런트, 백업·복구 절차
- Flyway V1~V18 순방향 기준선

## 4. 아직 입증하지 않은 경계

- 실제 도매꾹 응답 20~30건의 가격, MOQ, 구간가, 재고, 배송비와 화면 일치
- 가격 변경·품절·쿼터 응답에서 재확인 상태와 승인 해제가 기대대로 동작하는지
- 실제 공급처 CSV/XLSX/PDF의 병합 셀, 다단 헤더, 다중 페이지와 OCR 오류 유형
- 실제 S3/MinIO 보관, 백업, 복원과 보존·삭제 정책
- 실제 해외 구매·배송·관세·부대비용을 포함한 예상 원가와 실제 원가 차이
- 실제 SMTP 수신, 운영 도메인, 인증서, 관리자 생성, 모니터링과 장애 대응
- 외부 사용자의 반복 사용, 지불 주체, 현재 지출, 가격 수용성

샘플 성공을 실거래 성공이나 PMF 근거로 사용하지 않는다.

## 5. Git 기준선과 브랜치 정리 원칙

인계 직전 `feature/end-to-end-trade-cycle`은 작업 트리가 깨끗하고 원격 같은 이름의 브랜치보다
12개 커밋 앞서 있었다. `main`은 초기 커밋에 머물러 있어 현재 HEAD보다 45개 커밋 뒤에 있다.
과거 로컬 기능·리팩터 브랜치는 모두 현재 HEAD의 조상이다.

정리 순서는 다음과 같다.

1. 이 인계문서를 종료 브랜치에 커밋하고 원격 브랜치에 반영한다.
2. 종료 브랜치를 `main`으로 보내는 PR을 만들고 전체 검증 결과를 첨부한다.
3. PR 병합 전에는 원격의 과거 브랜치를 삭제하지 않는다.
4. 병합 후 `main`에서 `feature/v0-real-data-validation`을 시작한다.
5. 폐기된 `origin/feature/ai-server`의 마지막 커밋은 ADR-0001과 충돌하므로 병합하지 않는다.
6. 다음 단계에서는 적용된 V1~V18 migration을 수정하지 않고 V19부터 추가한다.

## 6. 다음 핵심 단계: V0 실데이터 검증

### V0V-0 — 기준선 보호

- 종료 브랜치 원격 반영과 `main` PR
- 백엔드, 프런트, E2E, Compose 검사를 CI의 필수 검사로 구성
- 공개 배포 전 npm 감사 결과를 런타임·빌드타임으로 분류

완료 기준: 새 작업이 재현 가능한 자동 검사 위에서 시작된다.

### V0V-1 — 파일럿 입력과 측정 계약

- 서로 다른 조달 경로의 실제 또는 실행 가능한 상품 3개 선정
- 최소 1개는 실제 해외 구매·배송·비용 자료를 가진 상품으로 지정
- 원본 자료의 사용·보관 권한과 익명화 범위 기록
- 시작 시각, 검토 수정 필드 수, 누락 항목, 예상/실제 원가 차이, 다음 결정 기록

완료 기준: 기능을 더 만들지 않고도 3개 상품의 검증표와 증거 위치를 설명할 수 있다.

### V0V-2 — 실제 거래 사이클 완주

1. 상품과 공급처·견적 원본 등록
2. 예상 원가 확정과 미확인 값 기록
3. 발주·선적 또는 국내 입고 진행
4. 실제 비용과 판매가능수량 마감
5. 판매 또는 구매의향 관측 입력
6. 재발주·관찰·중단 중 하나를 이유와 함께 결정

완료 기준: PRD의 V0 성공 조건을 실제 증거로 충족하고 기존 Excel·폴더 방식과 시간을 비교한다.

### V0V-3 — 필요한 연동만 실증

- 도매꾹 키가 있으면 주문 API 없이 검색·상세 20~30건을 읽기 전용 대조
- 실제 공급처 문서가 있으면 익명 회귀 fixture와 행별 기대값 작성
- 문서 기능을 쓰는 파일럿이면 MinIO/S3와 OCR worker 왕복 테스트 실행
- 실증에서 발견한 필드만 수정하고 새로운 공급처·채널 어댑터는 추가하지 않는다.

완료 기준: 실제 실패를 회귀 테스트로 남기고 샘플과 라이브 결과를 구분한다.

### V0V-4 — 외부 검증과 다음 판정

- 같은 세그먼트 적격 인터뷰 8~12건
- 익명 실제 자료 5세트 이상
- 일정이 정해진 외부 파일럿 3건
- 최소 3명이 자기 자료를 입력하고 2명이 두 번째 건을 만드는지 확인

완료 기준: V0.5 자동화, V1 SaaS, 또는 문제·세그먼트 재정의 중 하나를 근거로 선택한다.

## 7. 다음 작업의 우선순위

1. 기준선 원격 반영과 CI
2. 실제 3-SKU 파일럿 입력·측정 계약
3. 실제 해외 거래 1건 완주

5. 인터뷰와 외부 파일럿
6. 결과가 나온 뒤에만 자동화·성능·UI 고도화

실데이터 파일럿을 지연시키지 않는 범위에서 진행한다.

## 8. 인계문서 유지 규칙

각 단계 종료 시 이 문서 형식으로 다음을 남긴다.

- 종료 날짜, 브랜치, 기준 커밋
- 완료한 사용자 흐름과 의도적으로 제외한 범위
- 실제 실행한 검증 명령, 통과·실패·skip 수
- 실데이터와 합성 데이터의 구분
- 외부 시스템에 실제로 적용한 내용과 템플릿만 준비한 내용의 구분
- 다음 단계의 입력, 순서, 완료 기준과 중단 조건

후속 문서는 과거 결과를 덮어쓰지 않고 새 파일로 남기며, `docs/README.md`가 최신 인계문서를
가리키도록 갱신한다.
