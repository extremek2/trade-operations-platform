# 공급 문서·파일 변형 검증

- 날짜: 2026-09-22
- 상태: 저장소의 합성 CSV/XLSX·텍스트 PDF·블러 스캔 검증 완료. 실제 공급처 샘플 검증 대기.
- 실제 공급처 파일: 아직 첨부되지 않음. 아래 결과를 실거래 문서 검증으로 간주하지 않는다.

검증 명령: `./gradlew test --no-daemon`(전체 통과), 기존 `trade-ops-ocr:test` 이미지에서
`ocr-worker/tests/test_worker.py`(3개 통과), 프런트엔드 `CI=true npm test -- --watchAll=false --runInBand`
(55개 통과). 텍스트 PDF는 `pdftotext -layout` 출력으로 후보 매핑을 확인했다.

## 합성 샘플에서 확인한 결과

| 입력 | 확인 결과 | 남은 경계 |
|---|---|---|
| UTF-8 CSV | BOM, 따옴표 안 쉼표, 영문 헤더와 행 위치를 기존 파서 테스트로 확인 | 실제 공급처 인코딩·헤더 변형 |
| XLSX | 상품 4행 중 숫자가 아닌 단가와 단위 누락을 행별 오류로 남기는 기존 테스트 확인 | 병합 셀, 다단 헤더, 표시 형식 |
| 텍스트 PDF | `pdftotext -layout` 출력에서 SKU 4행의 상품명·MOQ·단위·단가·원산지를 후보로 추출. 제목·거래 조건도 삭제하지 않고 검토 행으로 보존 | 다른 표 순서·통화 표기·다중 페이지 |
| 블러 스캔 PDF | 기존 OCR 이미지에서 3개 worker 테스트 통과. 실제 추출 텍스트의 `JP- 001` SKU 공백을 정규화해 후보로 연결 | 상품명 오인식, 스탬프·손글씨·기울임·다단 표 |

블러 스캔의 추출 신뢰도는 89.33%였지만 첫 상품명 일부가 `스테인리스 Yee`로 잘못 읽혔다.
따라서 신뢰도만으로 상품 정보를 승인하지 않는다. 원문과 추출 텍스트를 함께 보여 주고 모든
초안 행을 `PENDING`으로 둔다. 표 행이 알려진 구조와 일치할 때만 값을 제안하며, 맞지 않는
행은 원문 그대로 남긴다. 잘못된 가격 구분자나 수량 범위는 자동 확정하지 않는다.

## 실제 파일을 받으면

1. 공급처별 원본 형식·시트/페이지 구조와 필수 열을 기록한다.
2. 개인정보와 거래 비밀을 가린 회귀 샘플을 만든다.
3. 상품 행 누락, 잘못된 열 매핑, 금액·수량 오인식, 출처 위치를 원본과 행별로 대조한다.
4. 확인된 변형에 한해 파서 규칙과 회귀 테스트를 추가한다.

실제 샘플이 없으므로 이번 단계에서 공급처별 정확도나 자동 승인 가능성을 주장하지 않는다.
