## 구현 내용

V8은 `purchase_selection`과 `purchase_selection_line`을 추가한다. 선택 행은 제안 원본 행,
희망 수량, 생성된 상품과 견적 행을 연결한다. 선택 행을 DB에서 유일하게 제한하므로 같은 제안 행은
두 번 반영되지 않는다. 사용자는 확인된 행 일부를 먼저 선택하고 나머지를 이후 별도로 선택할 수 있다.

`POST /api/v1/supplier-offer-drafts/{draftId}/selections`은 확인된 행 번호, 희망 수량과 선택적인
기존 상품 ID를 받는다. 다른 조직 상품, 제외된 행, 중복 행, MOQ보다 적은 수량과 단위 미확인 행은
거절한다. 신규 상품은 `SOURCING` 상태와 상태 이력을 남긴다. 선택된 행만 `DRAFT` 견적에 들어가며,
견적 수신·선택과 발주 승인은 기존 화면에서 사용자가 따로 결정한다. `GET /api/v1/purchase-selections`
과 단건 조회는 조직 범위 안에서 선택 결과를 반환한다.

새 `공급 상품 제안` 화면에서 수동 원본 입력, 행별 확인·제외, 추출 확인, 일부 행의 구매 선택과
선택 이력을 처리한다. 선택 결과에서 공급 견적 화면으로 이동할 수 있고, 수신된 견적을 선택하면
예상 원가 화면이 구매 희망 수량을 주문수량에 채운다.

## 검증과 남은 작업

PostgreSQL 통합 테스트는 V8 설치·JPA 검증, 추출 확인 전 선택 차단, 제외 행·MOQ 미달 차단,
부분 선택·중복 차단, 조직 격리, 선택 견적 수신과 예상 원가 생성까지 검증한다. 화면 테스트는
선택된 한 행과 희망 수량만 API에 전달하고 예상 원가 입력에 수량을 가져오는지 검증한다.
백엔드 전체 116개, 프런트엔드 전체 49개 테스트가 통과했고 프런트엔드 배포 빌드와 개발 Compose
문법 검사도 통과했다. 배포 리허설은 V8을 포함한 새 PostgreSQL 설치·백업·복원과 후검사를 검증한다.
이는 일회용 검증 환경의 결과이며 실제 운영 DB 적용은 아니다.

현재 PO 생성은 원가 시나리오 한 품목으로 제한되어 있다. 다음 단계에서는 선택 견적의 여러 행을
하나의 다품목 PO로 연결하되 견적 수량과 발주수량을 혼동하지 않아야 한다. 실제 파일 저장,
Excel/PDF 파서, OCR, 이메일과 외부 공급처 API는 아직 구현하지 않았다. 실제 운영 DB 적용도 하지 않았다.
