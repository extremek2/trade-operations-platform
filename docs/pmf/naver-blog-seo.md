# 네이버 블로그 SEO — 단일 파일판

## 절대 경계

이 스킬의 끝은 **네이버 스마트에디터 임시저장과 재조회 검증**이다. 공개·발행·게시·예약 버튼은
어떤 경우에도 누르지 않는다. 발행 코드를 만들지도 않는다. 사용자가 임시저장본을 직접 읽고 고친
뒤 사람의 손으로 발행한다.

자동 로그인은 금지한다. 로그인되지 않았으면 사용자가 직접 로그인하게 하고 멈춘다. 이 파일만
사용하며 별도 스크립트·참조·템플릿을 찾지 않는다.

## 결과 경로

```text
~/Downloads/AI마케팅실습/06_블로그/
├── keywords.csv
├── competitors.md
├── drafts/post_001.md ...
├── upload_log.csv
└── checkpoint.json
```

`01_내비즈니스/icp.json`과 `05_발송기록/replies.csv`가 있으면 읽기만 하여 고객 조건과 실제 고객
언어를 활용한다. 다른 제품 데이터가 섞였으면 사용하지 않는다.

## 0. 준비

브라우저가 필요하면 기존 로그인 브라우저나 제공된 브라우저 도구를 사용한다. 사용자의 브라우저에
붙었다면 전체 브라우저를 닫지 않는다. 한 편집 탭은 조립부터 임시저장 재조회까지 한 작업이 끝까지
소유한다.

필요한 값:

- 블로그 ID — 로그인 상태에서 확인하거나 사용자에게 질문
- 제품·고객·고객 문제
- 시드 키워드 — 자동 후보를 제시한 뒤 사용자가 선택
- 말투와 독자 수준 — 없으면 과장 없는 설명체

## 1. 키워드 조사

시드가 없으면 다음 순서로 후보를 만든다.

1. `replies.csv`의 고객 원문
2. `icp.json`의 겪는 문제와 검색 가능한 특징
3. 사용자 제품 설명
4. 그래도 없으면 한 번 질문

네이버 자동완성, 연관검색어, 실제 검색 결과를 조사한다. 최신 검색 결과와 숫자는 웹에서 직접
확인하며 기억으로 만들지 않는다. 시드, 자동완성, 연관 키워드를 합치고 중복과 검색 의도가 다른
후보를 제거한다.

후보별로 다음을 기록한다.

```text
키워드,유형,블로그문서수,최근30일글비율,검색의도,추천도,추천사유,측정일
```

- 문서 수가 정확히 안 보이면 `측정불가`, 상한만 보이면 `1000+`처럼 사실대로 쓴다.
- 최신 글 비율은 확인한 상위 결과 중 최근 30일 글의 비율이다.
- 추천도는 경쟁도만 보지 말고 제품 적합성과 사용자의 답변 가능성까지 고려한다.
- 첫 글 후보 3개를 `상`으로 추천하되 근거를 적는다.

사용자에게 세 후보와 수치를 보여주고 하나를 선택받는다. 사용자가 이미 키워드를 지정했다면 그
키워드를 보존한다.

## 2. 상위 노출 글 구조 분석

선택 키워드로 현재 네이버 검색 결과를 열어 관련 블로그 글 5~10개를 분석한다. 광고, 중복,
키워드와 무관한 결과는 제외하고 제외 이유를 기록한다. 문장을 복사하지 않는다.

각 글에서 확인할 것:

- 제목과 키워드 위치
- 공백 제외 본문 글자 수
- 소제목 수와 질문형 소제목
- 이미지 수
- 도입부가 검색 의도에 답하는 방식
- 태그
- 발행일과 최신성
- 독자에게 요구하는 다음 행동
- 다른 글에는 없는 실제 경험·수치·사례

`competitors.md` 구조:

```markdown
# 상위 글 분석: {키워드}
- 조사일, 검색 결과 범위, 유효 표본 수

## 글별 관찰
| 순위 | 제목 | URL | 글자 수 | 소제목 | 이미지 | 발행일 | 구조 메모 |

## 공통 구조
1. 제목 패턴
2. 평균·중앙 글자 수
3. 도입부 패턴
4. 소제목과 이미지 패턴
5. 우리가 추가할 고유 정보
```

페이지에서 확인할 수 없는 수치를 추정하지 않는다.

## 3. SEO 초안 작성

상위 글 구조는 참고하되 문장을 베끼지 않는다. 사용자의 제품 경험, 고객 원문, 직접 확인한 사실을
중심으로 쓴다. 모르는 사례·성과·통계를 만들지 않는다.

`drafts/post_NNN.md` 형식:

```markdown
---
제목: 주요 키워드가 앞쪽에 있는 20~40자 제목
키워드: 주요 키워드
보조키워드: 쉼표로 구분
태그: 5~10개, 쉼표로 구분
이미지: 절대경로를 쉼표로 구분하거나 비움
목표글자수: 숫자
생성시각: YYYY-MM-DD HH:MM:SS
---

도입부 2~3문단. 첫 문단에 주요 키워드를 넣고 검색 의도에 바로 답한다.

[[이미지:1]]

## 1. 첫 소제목

구체적인 설명, 경험, 사례.

## 2. 질문형 소제목은 무엇인가요?

독자가 실제로 궁금해하는 질문에 답한다.

[[이미지:2]]

## 3. 적용 방법

순서와 주의점을 설명한다.

## 정리하면

핵심 요약과 댓글·이웃추가·문의 중 하나의 자연스러운 CTA.
```

본문에 URL을 그대로 넣지 않는다. 스마트에디터가 링크 미리보기 카드를 자동 생성해 구조가
흐트러질 수 있다. 링크가 필요하면 표시 텍스트만 두고 사용자가 발행 전에 직접 연결하게 한다.

이미지가 없으면 존재하지 않는 파일을 만들지 않는다. 이미지 자리가 필요한 이유와 권장 이미지를
구체적으로 메모하되, 업로드 단계에서는 실제 파일이 있는 항목만 사용한다.

## SEO 체크리스트 12개

초안 직후 전부 검사하고 표로 `통과/미통과`, 실제값, 수정 내용을 보여준다.

1. 제목 앞쪽 절반 안에 주요 키워드가 그대로 있다.
2. 제목이 20~40자다.
3. 도입부 첫 문단에 주요 키워드가 있다.
4. 소제목이 3~5개다. `정리하면`은 별도로 센다.
5. 소제목 중 최소 1개가 질문형이다.
6. 본문이 공백 제외 1,000자 이상이고 가능하면 상위 글 목표 분량에 맞는다.
7. 주요 키워드가 본문에 3~8회 등장한다.
8. 이미지 자리 표시가 2곳 이상이다. 실제 이미지가 없으면 업로드 전 사용자에게 알린다.
9. 태그가 5~10개다.
10. 태그에 주요 키워드와 띄어쓰기 제거 변형이 포함된다.
11. 마지막에 독자의 다음 행동을 제시하는 CTA가 있다.
12. `[채워 넣을 자리]`, `{{변수}}`, TODO 같은 미완성 표시가 없다.

미통과 항목은 가능한 범위에서 직접 고치고 다시 검사한다. 사실 자료나 사용자 경험이 필요한
부분은 지어내지 말고 사용자에게 한 번에 필요한 최소 질문을 한다. 12개가 통과하기 전에는 업로드
단계로 가지 않는다.

## 4. 스마트에디터 조립과 임시저장

업로드 직전 사용자에게 제목과 초안 경로를 보여주고 임시저장 작업을 시작해도 되는지 확인한다.
명시적 동의 후에만 네이버 편집기를 수정한다.

### 안전한 조립 순서

1. 깨끗한 새 편집기를 확보한다.
2. 자동복구본을 이어 쓸지 묻는 창은 취소한다.
3. 제목을 입력하고 제목 서명으로 확인한다.
4. 본문을 논리적인 한 줄씩 실제 키 입력으로 넣는다. 긴 HTML을 한 번에 주입하지 않는다.
5. `1. `처럼 자동 목록으로 변환되는 줄은 숫자 뒤에 U+2060 word joiner를 넣어 모양을 보존한다.
6. 이미지는 앞 문장의 정확한 내용 서명을 기준으로 문서 순서대로 삽입한다.
7. 태그는 본문 해시태그로 넣는다. 발행 설정 패널은 열지 않는다.
8. 위에서 아래까지 스크롤하며 제목, 각 구간 마지막 문장, 이미지 파일명, 태그를 누적 확인한다.
9. 임시저장을 누른다. `발행`, `공개`, `게시`, `예약` 버튼은 절대 누르지 않는다.
10. 임시저장 목록에서 같은 제목을 다시 선택한다.
11. 서버에서 재조회한 제목과 본문 마지막 문장을 확인한다.
12. 검증 후 제어 연결만 끊고 사용자의 브라우저는 열어 둔다.

### 성공 판정

로컬 편집 화면만 보고 성공이라 하지 않는다. 다음 두 조건이 모두 필요하다.

- 임시저장 목록에 정확한 제목이 존재한다.
- 그 항목을 다시 열었을 때 본문 마지막 문장이 존재한다.

스마트에디터는 화면 밖 요소를 DOM에서 내릴 수 있으므로 순간 컴포넌트 개수로 전체를 판정하지
않는다. 문서 위부터 아래까지 스크롤하며 고유 `data-compid`와 콘텐츠 서명을 누적한다.

### 선택자 실패

편지기 요소나 버튼을 못 찾으면 후보 선택자를 순서대로 시도하되, 실패한 선택자와 현재 URL,
로그인 여부를 한국어로 출력하고 멈춘다. 조건 숫자를 임의로 완화해 성공 처리하지 않는다.

## 체크포인트

각 단계 뒤 `checkpoint.json`을 임시 파일에 완전히 쓴 뒤 원자적으로 교체한다.

```json
{
  "blog_id":"",
  "draft_path":"/절대/경로/post_001.md",
  "title":"",
  "steps":[
    {"step":"editor_ready","action":"새 편집기","signature":"URL","updated_at":"ISO-8601"},
    {"step":"title","action":"제목 입력","signature":"정확한 제목","updated_at":"ISO-8601"},
    {"step":"body","action":"본문 입력","signature":"마지막 문장","updated_at":"ISO-8601"},
    {"step":"draft_saved","action":"임시저장","signature":"저장목록 제목","updated_at":"ISO-8601"},
    {"step":"reloaded","action":"재조회","signature":"마지막 문장","updated_at":"ISO-8601"}
  ]
}
```

재실행 시 앞에서부터 연속으로 확인된 마지막 단계 다음부터만 진행한다. 앞 단계 기록 없이 뒤 단계가
있으면 비연속 상태이므로 멈춘다. 제목이 같은 임시저장본이 여러 개 있어도 제목만 보고 삭제하지
않는다. 저장 시각·마지막 문장·이미지 순서를 비교하고 확신이 없으면 그대로 둔다.

`upload_log.csv`:

```text
날짜시각,제목,초안경로,상태,검증내용,블로그ID
```

`상태`는 `임시저장 확인`, `검증 실패`, `사용자 확인 필요`처럼 사실대로 쓴다. 공개 발행 상태를
이 스킬이 기록하지 않는다.

## 완료 보고

사용자에게 다음을 제공한다.

- 선택 키워드와 추천 근거
- 상위 글 표본 수와 목표 글자 수
- 12개 SEO 체크 결과
- 초안 파일 경로
- 임시저장 및 재조회 성공 여부
- 네이버 글쓰기 화면과 찾을 제목
- “내용을 직접 확인한 뒤 사람이 발행 버튼을 눌러야 한다”는 안내

공개 발행을 했다고 말하지 않는다. 검색 노출 검사는 사용자가 실제로 발행한 뒤 별도 요청할 때만
수행하며, 최신 공개 URL과 검색 결과를 직접 확인한다.
