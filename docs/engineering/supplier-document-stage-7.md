# P6 일곱 번째 단계: 실패한 문서 추출 재시도

- 날짜: 2026-09-22
- 상태: 백엔드 구현·합성 문서 통합 검증 완료. 화면 조작과 운영 자동 재시도는 범위 밖.

## 처리 흐름

1. `POST /api/v1/supplier-documents/{documentId}/extractions/retry`는 조직 소유 문서의 **최신 추출이 실패한 경우에만** 받는다. OWNER·ADMIN·OPERATOR가 실행할 수 있다.
2. 객체 저장소의 원본 크기와 SHA-256을 먼저 확인한다. 저장소 또는 OCR 연결이 꺼져 있거나 원본 무결성이 맞지 않으면 새 시도 이력을 만들지 않는다.
3. 문서 행에 쓰기 잠금을 잡고 새 `ExtractionRun`을 만든다. 이전 성공·실패 이력은 수정하지 않는다. 재추출에 실패해도 새 실패 이력과 메시지를 남긴다.
4. `GET /api/v1/supplier-documents/{documentId}/extractions`는 최신 순으로 상태·방식·버전·점수·오류·시각을 반환한다. 다른 조직의 문서는 조회하거나 재시도할 수 없다.
5. 재추출이 성공하면 기존 문서 검토 초안 생성 API가 최신 성공 이력을 사용한다. 이미 성공한 문서는 재시도할 수 없다.

V13은 문서의 반복 추출을 허용하고, 수동·CSV·XLSX 추출의 기존 `원본+추출기 버전` 유일성은 부분 인덱스로 유지한다. 최신 이력은 생성 시각이 같아도 순서가 정해지도록 ID 내림차순으로 읽는다.

## 검증 경계

- 합성 PDF로 첫 추출 실패 → 다른 조직의 재시도 차단 → 성공 재시도 → 두 이력 보존 → 재시도 중복 차단 → 새 이력에 연결된 검토 초안 생성을 확인한다.
- `./gradlew test`: 전체 133개 중 132개 통과, 1개 skip, 실패 0건. 배포 리허설의 최신 Flyway 버전 확인도 V13으로 갱신했다.
- 실제 공급처 파일의 오류 유형과 자동 재시도 정책은 첨부파일을 받은 뒤 검토한다.
